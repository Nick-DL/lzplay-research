# 第二阶段研究需求

在上一阶段，我们已经：

- 解包，并证明lzplay被完全解除加固是比较困难的；
- 复刻了一个App LZRevive，目前有效的功能包含检测设备状态、GSF信息等；
- 使用了lzplay的姊妹App旅游助手、Chat Partner等研究了LZplay的工作原理；
- 研究了备份还原法的可行性，以及其中改时间、设置“允许自启动、后台运行”等的必要性。

目前阶段仍然需要解决两个问题：

- **寻找一种备份还原的替代方案**。我们万一可以探索出一种不需要费尽周折操作备份还原、无需用户再收集谷歌框架的几个apk的方法呢？
- **解决SafeNet认证问题**。网上现有的教程都没有一种妥善解决设备注册的方法，我的Mate 50 Pro装好GMS不久就弹出来了“此设备未获得Play保护机制认证”的弹窗。

关于第一个问题，目前设想的方案如下：

我们可以开发一种特定的VPN代理软件，拦截旅游助手/Chat Partner的联网流程前后传送的数据，并返回某些能帮助快速跳过相关流程的数据，从而帮助他们走内置流程，安装提前预置的apk，并完成提权。为什么不针对Lzplay呢？因为其源码被加固，机制还不够公开透明。

可能暂时解决不了平板缺少相关MDM api的问题。不过没关系。

具体的研究流程大致如下：

1. 研究联网流程。  
先明白二者的具体工作流程。什么时候检测更新，什么时候注册SafeNet，什么时候给GMS提权？先后顺序呢，哪些步骤要联网？
2. 调试VPN。可以合并进LZrevive。新增“两个页签”的App布局，1个是新增的代理功能，另一个是原来的查权限信息，仿lzplay的功能。
3. 在旅游助手/Chat Partner中调试。如果安装后发现会在某一部卡住，可以修改包，加探针调试，通过后再用原版继续研究，以免无法提权。允许在测试中App的来回装卸。

关于第二个问题，考虑到SafeNet注册时对于未注册的设备，好像需要设备的硬件开发者用root权限去get到一些信息，再联网提交（具体需要看谷歌的文档求证）。我认为第一个问题的研究有助于这个研究，因而我们需要先让第一个VPN的工作几乎顺利完成，再进行这一个问题的研究。
