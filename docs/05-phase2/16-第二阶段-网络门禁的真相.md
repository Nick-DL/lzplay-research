# 第二阶段：网络门禁的真相（探针实测）

> **两个流行假设都被实测证伪。真正的失败点是 App 连接 Google 时的网络可达性。**

---

## 一、被证伪的两个判断

### ❌ 判断①「检查方式不兼容 Android 10+」

**假设**：`NetworkUtil.a()` 用 `getAllNetworkInfo()`，该 API 在 API 29+ 返回 null ⇒ 门禁秒失败。

**实测（LZRevive `NetProbe`，Mate50 / HarmonyOS 4.2 / SDK 31）** ：

```
getAllNetworkInfo()      = length=15          ← 不是 null！
  [1]  type=1  typeName=WIFI  state=CONNECTED connected=true
  [14] type=17 typeName=VPN   state=DISCONNECTED connected=false
getNetworkInfo(TYPE_WIFI) = WIFI CONNECTED=true
  -> app 的 NetworkUtil.b() 会返回 true
getActiveNetwork()        = 121, transports: WIFI
  INTERNET=true VALIDATED=true NOT_RESTRICTED=true
```

**⇒ 华为保留了 `getAllNetworkInfo()` 的兼容实现，返回 15 条记录。门禁不短路。**

### ❌ 判断②「App 不希望挂 VPN 连谷歌」

**实测**：VPN 处于 **DISCONNECTED**（Clash 关闭），`getNetworkInfo(TYPE_WIFI)` 仍返回
`connected=true`，**但 App 照样弹「连接谷歌网络异常」**。

**⇒ 与 VPN 无关。代码里也没有任何 VPN 判断。**

## 二、真正的失败点（决定性证据）

`NetProbe` 复刻了 App 的 `HttpUtil.a()` 逻辑（GET `https://www.google.com`，
15 秒连接 + 15 秒读取，重试 2 次）：

```
attempt FAILED in 30071 ms: java.net.SocketTimeoutException:
    failed to connect to www.google.com/2001::1 (port 443)
    from /2409:8970:17d4:73e:58ee:f70a:6e38:67e1 (port 34838) after 15000ms

attempt FAILED in 30050 ms: 同上

HttpUtil.a() would return  = false
total time                 = 60131 ms
detail                     = SocketTimeoutException
```

### 关键信息

| 项 | 值 |
|---|---|
| 连接目标 | **`2001::1`** —— **IPv6 地址** |
| 本地地址 | `2409:8970:...` —— 中国移动 IPv6 |
| 异常 | `SocketTimeoutException`（15 秒） |
| 结果 | 两次失败，共 **60 秒** |

**⇒ `HttpURLConnection` 选中了 IPv6 地址去连 Google，而国内 IPv6 到 Google 不通，
15 秒超时后重试，再 15 秒，`HttpUtil.a()` 返回 false ⇒ App 弹「网络异常」。**

**对比**：shell 里 `curl` 能返回 200，是因为 **curl 有 Happy Eyeballs**（IPv6 失败
自动回退 IPv4）。**App 用的 `HttpURLConnection` 在这个环境下没有回退。**

### 完整的失败链

```
设备无梯子
   ↓
App 解析 www.google.com 得到 IPv6 (2001::1)
   ↓
IPv6 到 Google 不通 → SocketTimeoutException（15s × 2）
   ↓
HttpUtil.a() 返回 false
   ↓
UpdateInstance.c() 的失败回调 a$1.a()
   ↓
a$1.a() → new a$1$1 → SplashActivity.runOnUiThread()
   ↓
弹出 R.string.register_net = "连接谷歌网络异常，请检查网络链接。"
```

## 三、代码路径（原版，从原版 APK 重新反编译确认）

```
SplashActivity.onCreate()
   └─ new DeviceHelper(splash)                     // com/x/plus/pro/a/a
      └─ a.b = new DeviceManage(activity)          // com/x/plus/pro/a/b
         └─ if (DeviceManage.a(ctx)) {             // ★ 门禁
                UpdateInstance.e(ctx);             // 构造请求体（会读已装 APK 算 MD5）
                list = UpdateInstance.c(ctx);      // 网络请求，回调 a$1
                if (list != null && size > 0) { 显示更新框; return; }
            } else {
                handler.sendEmptyMessageDelayed(0x65, 10);   // → a/a$2.a(100) → 弹窗
            }
```

### 门禁 `DeviceManage.a(Context)` 的真实语义

```java
if (SDK_INT < 28) return false;
DevicePackageManager pm = new DevicePackageManager();
ComponentName cn = new ComponentName(ctx, DeviceManageReceiver.class);
try {
    List l = new ArrayList(); l.add(ctx.getPackageName());
    pm.getSysAppList(cn, l);                       // 华为 MDM 特权 API
} catch (Throwable e) {
    if (e instanceof NoSuchMethodError) return false;
    if (e.getClass().getName().equals(
        "com.huawei.android.util.NoExtAPIException")) return false;
}
return true;
```

**它检查的是「华为 MDM 特权 API 是否可用」，与网络无关。**

**`GateProbe` 实测**：
```
DevicePackageManager = FOUND methods=30 from=<bootstrap / framework>
getSysAppList        = returned []
```
**返回空列表但没有抛异常 ⇒ 门禁返回 `true` ⇒ App 继续走到网络检查。**

### 两个弹窗入口

| 消息 | 触发条件 | 显示 |
|---|---|---|
| `0x64` (100) | 走到 `else` 分支（门禁 false） | `R.string.register_net` = **连接谷歌网络异常** |
| 其它 | `a$1.a()` 失败回调 | 同上（`a/a$1$1` → `runOnUiThread`） |

## 四、对方案的直接影响

### 结论：**必须让 App 认为「Google 可达」**

这就是委托里说的"外挂 VPN"要解决的事 —— 但**目标不是伪造 `api.trip-happy.com`，
而是先让 Google 检查通过**（或者说两者都要）。

| 障碍 | 位置 | 外挂 VPN 能否解决 |
|---|---|---|
| **Google 可达性** | `HttpUtil.a()` GET `https://www.google.com` | ✅ **可以** —— 代理该请求返回 100–399 即可 |
| 死服务器 `api.trip-happy.com` | `UpdateInstance.c()` | ✅ 可以 —— 伪造合法响应 |
| 死 CDN | FileDownloader | ✅ 可以 —— 但实测**不需要**（APK 从 assets 本地解包） |
| WiFi/VPN 状态 | `NetworkUtil` | ✅ 实测**不是障碍** |

### 代理需要实现的最小集合

```
① 拦截 https://www.google.com            → 返回 200（或任意 100–399）
② 拦截 https://api.trip-happy.com/index.php/upgrade/info/  → 返回合法协议响应
③ www.google.com/android/uncertified     → 【不要】拦截（真服务器活着，注册要用）
```

**注意 ① 是 HTTPS，需要中间人证书；或者更简单：让代理直接走真梯子。**
**② 也可以走真梯子，但服务器已死，所以必须伪造。**

## 六、复现方式

```powershell
# 构建 LZRevive（含 NetProbe）
. work\tools\build_apk.ps1
Build-AndroidApp -Proj "work\revive" -Name "LZRevive2" -Out "$PWD\work\LZRevive2.apk"

# 安装、运行、取结果
adb -s <serial> install -r -g work\LZRevive2.apk

adb -s <serial> pull /sdcard/Android/data/com.lzplay.revive/files/lzrevive-net.txt .
```

**`NetProbe` 做了什么**：
- 报告 `getAllNetworkInfo()` 是否为 null 及其全部条目
- 报告 `getNetworkInfo(TYPE_WIFI)` / `TYPE_MOBILE` / `getActiveNetworkInfo()`
- 报告 `getActiveNetwork()` 的 transports 与 INTERNET/VALIDATED 能力
- **复刻 App 的 Google 检查**（含重试与超时），记录每次的实际异常与耗时
- 结果自动写入 `lzrevive-net.txt`（不依赖用户点击）
