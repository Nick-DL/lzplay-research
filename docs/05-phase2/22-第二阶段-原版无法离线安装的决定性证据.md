# 第二阶段：原版在 Android 12 上无法离线安装（决定性发现）

> **实测 + 代码双向证实：旅游助手原版按 `SDK_INT` 查找预置资产，而 APK 里只有
> `_28` / `_29` 两套。Mate50 是 SDK 31 ⇒ 必然解包失败 ⇒ 回退到已死的 CDN。**
>
> **⇒ 「不改包」这条路在 Android 12 上不成立。**

---

## 一、实测证据

设备：Mate50 Pro `DCO-AL00`，**`ro.build.version.sdk = 31`**（Android 12 / HarmonyOS 4.2）

现场操作：用导出广播进入 `MainActivity`（**成功绕过了 Splash 的联网请求**），
点「立即更新」→ 设备管理器激活 → 权限授予 → 再点「立即更新」→ 确认卸载对话框「好」。

结果（监控 240 秒）：

```
t+  5s  com.qiyecomm/com.x.plus.pro.MainActivity   ★新装: gmapjar
t+ 10s .. t+240s  MainActivity（无新装）
界面: "安装异常，请重试。"
```

**⇒ 一个包都没装上。**

---

## 二、代码证据：资产名按 SDK 版本拼

### 原版（`work/orig_smali/.../beans/config/ApkInfo.smali`）

```smali
:98    append(pkgName)
:100   const-string v2, "_"
:102   append("_")
:104   sget v2, Landroid/os/Build$VERSION;->SDK_INT:I     ← ★ 运行时取
:106   append(SDK_INT)
:108   const-string v2, ".apk"
:110   append(".apk")
```

**⇒ 资产名 = `<pkgName>_<SDK_INT>.apk`。Mate50 上即 `<pkgName>_31.apk`。**

### APK 里的实际资产（`work/travel_decoded/assets/`）

```
com.android.vending_28.apk / _29.apk
com.google.android.gms_28.apk / _29.apk
com.google.android.gsf_28.apk / _29.apk
com.google.android.syncadapters.contacts_28.apk / _29.apk
com.oversea.gmapjar_28.apk / _29.apk
com.google.android.gms.policy_sidecar_aps_28.apk
com.google.android.backuptransport_28.apk
idhelper.apk
```

**⇒ 只有 `_28` 和 `_29`，【没有 `_31`】。**

### 改包版（`work/travel_decoded/smali/.../ApkInfo.smali`）

```smali
:104   const/16 v2, 0x1d        ← 硬编码 29
```

**⇒ 早先的改包把 SDK 取值换成了常量 29 —— 这正是让离线解包能工作的关键改动。**

### 失败链

```
ApkInfo.a(Context)
  → assetName = pkgName + "_31.apk"
  → AssetManager.open("com.google.android.gms_31.apk")   ⇒ IOException
  → 解包失败（f/c.smali:269-439）
  → 回退到 FileDownloader 下载
  → downUrl = cdn-trip-happy.sg.ufileos.com 等【已死域名】
  → 60 秒超时
  → "安装异常，请重试。"
```

## 三、对既有结论的修正

**我此前多次断言「原版不需要改包」。这个说法不完整。**

准确的对照表：

| 能力 | 原版 | 改包版 |
|---|---|---|
| 启动是否崩溃（OOM） | ✅ 全新安装不崩（GMS 未装时无大文件可哈希） | ✅ 已修（流式 MD5） |
| **华为 MDM 静默安装特权** | ✅ **持有 8 项，含 `MDM_INSTALL_SYS_APP`** | ❌ **0/7（重签毁 `HUAWEI.CER`）** |
| **离线解包 assets** | ❌ **找 `_31`，不存在** | ✅ **硬编码 `_29`，可用** |
| 能否装 GMS | ❌ 回退到已死 CDN | ⚠️ 走标准安装器，缺 `REQUEST_INSTALL_PACKAGES` |

**⇒ 原版在 Android 12 上【没有任何可用路径】** —— 离线资产用不了，CDN 已死。

**⇒ 以下三条同时成立，互不矛盾：**
1. 原版**不需要**为 OOM 改包（全新安装不崩）
2. 原版**必须**为资产选择改包（否则 Android 12 上取不到预置包）
3. 改包**必然**丢掉 MDM 特权

## 四、这条路径的完整结论

### 走通的部分（真实成果）

```
✅ 导出广播 com.x.plus.pro.UpdateNotifyClick → 直进 MainActivity，绕过全部联网
✅ 按钮 → 设备管理器激活（含华为风险确认）→ 权限授予（GET_INSTALLED_APPS）
✅ 状态机启动：e/b.a() → e/b.b() → e/b.h()（解包阶段）
✅ "检测到设备已安装版本较旧" 是新安装的【正常预备步骤】，非异常
```

### 卡住的部分

```
❌ e/b.h() 解包阶段：找不到 com.google.android.gms_31.apk
❌ 回退 CDN → 死 → 60 秒超时 → "安装异常"
```

### 因此，「不改包 + 零 root + 零联网」三个目标**无法同时成立**

必须放弃其中一个：

| 放弃 | 代价 |
|---|---|
| 不改包 | 需在 manifest 补 `REQUEST_INSTALL_PACKAGES`（二进制 XML 补丁），且**没有 MDM 静默安装**，每个包会弹系统确认框 |
| 零 root | 装系统 CA 做 TLS 中间人 ⇒ 但代理只解决"服务器响应"，不解决"资产找不到" |
| 零联网 | 需要 CDN 复活（服务器已不存在） |

**⇒ 最实际的组合：改包（补权限）+ 用户点几次确认框。**

## 五、一个仍值得验证的推论

**原版持有 MDM 特权，而 MDM 的 `installPackage()` 接受【文件系统路径或 URI】。**

如果能让原版拿到**解出来的 `_29` APK**（而不是它自己去找 `_31`），
它是否能用 MDM 静默装完？

**障碍**：
- 解包由 `e/b.h()` 内部驱动，路径写死
- 预置缓存目录需要写 `/data/data/com.qiyecomm/cache/file/`（无 root 不可写，`run-as` 因无 `debuggable` 不可用）
- **但华为备份 App 可以写**（已证实无视 `allowBackup="false"`）

**⇒ 一条尚未验证的组合路径**：
```
用华为备份把 com.google.android.gms_29.apk 预置进
  /data/data/com.qiyecomm/cache/file/
但 e/b.h() 找的是 _31 —— 文件名仍不匹配
⇒ 除非连 ApkInfo 的资产名一起改（但那就要改包）
```

**⇒ 死结。改包不可避免。**

## 六、下一步

| 优先级 | 路线 | 说明 |
|---|---|---|
| **★** | **改包版 + 补 `REQUEST_INSTALL_PACKAGES`** | 唯一已知可行的完整路径。需二进制 XML 补丁（归档里有 4 个 bug 的修复经验 + 未尝试的"原地追加"思路） |
| ② | 拿到 root | 装系统 CA ⇒ 可让**原版**重新工作（代理提供 `_31`？不，代理无法解决资产名问题）—— **root 也救不了原版** |
| ③ | 接受现状 | 第一阶段目标已达成 |

**⚠️ 重要**：**root 也救不了原版** —— 因为问题是 APK **内部没有 `_31` 资产**，
而不是权限或信任问题。所以之前推荐的"拿到 root"在这条路上是无效的。

**⇒ 唯一出路是改包，且只需补一个权限声明。**
