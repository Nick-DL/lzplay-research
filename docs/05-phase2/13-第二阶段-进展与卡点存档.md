## 二、已排除的原因（都做过实验）

| # | 假设 | 如何排除 |
|---|---|---|
| 1 | APK 太大装不上 | `pm install` 同一个文件 → Success |
| 2 | 签名/版本冲突 | 同上，且 GMS 已完全卸载 |
| 3 | URI 权限未授予 | 加上 `FLAG_GRANT_READ_URI_PERMISSION`（`0x10000001`）后 URI 与标志都正确，仍失败 |
| 4 | FileProvider 路径配置错 | 实测 URI 是 `content://com.qiyecomm.provider/app_cachePath/...`，**`app_cachePath` 是已声明的内部缓存根**，配置正确 |
| 5 | `REQUEST_INSTALL_PACKAGES` 被拒 | `appops set ... allow` 后行为**完全没变**（69ms 退出） |
| 6 | 系统策略阻止 | `install_non_market_apps=1`，且 `pm install` 可装 |

**⇒ 剩下的唯一嫌疑：应用清单未声明 `REQUEST_INSTALL_PACKAGES`。**
`pm grant` 的报错是直接证据：
```
SecurityException: Permission android.permission.REQUEST_INSTALL_PACKAGES
    requested by com.qiyecomm ...        ← 该 app 未申请此权限
```
对未声明的权限，`appops` 的覆盖不生效 —— 这解释了为什么第 5 项实验无效。

## 三、当前卡点：修改二进制清单

### 目标

给 `AndroidManifest.xml` 加：
```xml
<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />
```

### 为什么不能简单重建

现有重建脚本的策略是"**只换 `classes.dex`**"，其余 504 个条目（含 120 MB assets）
逐字节复制。改清单意味着要让 aapt2 重新 link —— 它得处理那 120 MB，风险与耗时都高。

### 尝试过：直接改二进制 XML —— **目前不成功**

工具：`work/tools/patch_manifest_permission.py`

已修掉的三个 bug：
1. `headerSize` 写成 16，应为 **8**（`ResChunk_header` 的大小）
2. 元素插到了 `<manifest>` **之前**，必须先定位 `<manifest>` start element 再插到它后面
3. 属性块偏移算错：`ResXMLTree_node` 头是 **16 字节**，所以 `ns` 在 `pos+16`、`name` 在 `pos+20`
4. `rawValue` 填成了 rid（`0x01010003`），应为**字符串池索引**

修完之后：
- 字符串确实写进了池子（二进制里能找到 1 次）
- aapt2 **不再报解析错误**
- **但权限列表错乱**：从原来的完整列表变成只剩 3 条，且顺序不对

**⇒ 元素结构仍有问题。** 可疑点：

- 我替换了**整个字符串池**，而 **`resource-map` chunk 里的 rid 数组必须与池中前 N 个字符串一一对应**。如果新池里字符串的顺序或数量与 rid 数组不匹配，就会错乱
- 需确认：`resource-map` 的大小（100 字节 = 25 个 rid）是否等于新池里"有 rid 的字符串"数量

### 建议的正确做法

**方案 A（推荐）**：不要重建池。改为**复用池中已有的字符串**：
- `uses-permission` 这个 tag 名**已存在**（池里 index 79）
- 只需**追加一个**字符串：权限名
- **追加在池末尾**，前面所有字符串的索引不变 ⇒ **resource-map 不受影响**
- 然后只需修正池 chunk 大小与 XML chunk 大小

（我之前的实现就是这样做的吗？需要复查 `build_pool` 是否保持了原顺序并追加 —— 
它确实保持了顺序，但**重建池时的偏移与 padding 可能与原始不同**，
导致后续 chunk 的相对位置变化而未被正确修正。应改为**原地追加**：
解析出原池的确切字节布局，只在末尾追加新字符串，不动任何已有偏移。）

**方案 B**：用 apktool 反编译 → 改清单 → 重建。
代价：apktool 要处理 120 MB assets，且 `resources.arsc` 可能被重写（Chat Partner 就因此失败过）。

**方案 C（绕开）**：不改清单，改为**用 PackageInstaller 会话 API 安装**。
写一个几行的小工具 App，把 APK 从 assets 解出来 → 建 session → `session.commit()`。
**这条路 100% 可行**（`pm install` 就是它的命令行版），但需要用户先装这个工具 App。
