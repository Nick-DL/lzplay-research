# 第二阶段：预置应用数据可行性研究 + 一条被忽略的离线入口

> **两个结论：**
> 1. **预置数据无法绕过旅游助手的联网门禁**（两条独立理由，且有代码证据）
> 2. **⚠️ 但存在一条完全不经过服务器的入口** —— 我们之前漏掉了它，
>    它推翻了「唯一卡点 = 服务器已死」的说法

---

## 一、预置数据：**不可行**

用户提出的假设类比：LZPlay 当年靠备份还原**预置 app 数据**跳过了联网注册。

### 理由 ①：冷启动门禁**不看缓存**

`SplashActivity.onCreate` 的执行路径：

```
SplashActivity.smali:130   DeviceManage.a(ctx)          → 华为 MDM API 检查（无网络）
SplashActivity.smali:139   UpdateInstance.e(ctx)        → 清理，非门禁
SplashActivity.smali:144   UpdateInstance.c(ctx)        → 读 assets 清单（离线）
a/b.smali:215-247          【无条件 POST】               ← ★ 没有任何前置缓存检查
```

`update/c.smali:1540-1604`（真正发请求的方法）**完全不读 `updateUpgrade` 缓存**。

**缓存值 `com.x.plus.pro.update.updateUpgrade` 的全部读取点：**

| 读取点 | 何时可达 |
|---|---|
| `c.smali:449/459/474/492/516/535` | 通知构建 —— **只在 POST 成功之后** |
| `c.smali:1430` | 下载路径 —— 只在 POST 成功之后 |
| `c.smali:1695/1713`、`e.smali:114/128/145/161` | `MainActivity` 里 —— **冷启动到不了** |
| `e.smali:236/245` | 清理，仅副作用 |

**⇒ 预置缓存对冷启动流程毫无影响，App 照样卡在 Splash 等 POST。**

### 理由 ②：即使读了也没用 —— **签名死路**

缓存里能装的包，必须满足两条**同时成立**的签名校验：

```
c.smali:1617-1684   model.sign_1 必须 == f/i.b(ctx, ctx.getPackageName())
c.smali:696-772     model.sign_1 必须 == f/i.b(ctx, model.pkgName)
```

`f/i.b()` = **包签名证书 DER 的 MD5**。旅游助手的证书 MD5 实测为：

```
sign_1   = 7a19b6077a58aab4451e0bcbdb343ebe
sign_256 = 15e492495527ef0e99a18afc351356f0761b100a3ff187996f78542829312c5f
（从 META-INF/OVERSEA.RSA 提取 DER，CN=oversea, 749 字节）
```

**⇒ 最终交给 `DevicePackageManager.installPackage()` 的 APK，必须用【旅游助手自己的开发者私钥】签名 —— 我们没有。**

### 与 LZPlay 的类比为什么不成立

| | LZPlay | 旅游助手 |
|---|---|---|
| Splash 决策 | **先读持久化的 `userRegistered` 标志**，再决定是否联网 | **无条件联网**，无前置缓存检查 |
| 预置数据作用 | 让"已注册"标志为真 ⇒ 跳过注册 | 门禁读不到它 |
| 结构 | 门禁存在且可被数据满足 | **门禁根本不存在** |

**⇒ 类比结构上正确，但无法迁移。**

## 二、⚠️ 但发现了一条不经过服务器的入口

### `UpdateNotificationReceiver`

```
work/man_orig.txt:92-96     声明（带 intent-filter，targetSdk 29，未写 exported ⇒ 默认 true）
UpdateNotificationReceiver.smali:18-57   处理逻辑
```

**它的处理是无条件的：**

```java
// UpdateNotificationReceiver.smali
if (action.equals("com.x.plus.pro.UpdateNotifyClick")) {
    Intent i = new Intent(ctx, MainActivity.class);
    i.putExtra("isShowDialog", true);
    ctx.startActivity(i);        // ← ★ 直接进主界面
}
```

**⇒ 完全不经过 `SplashActivity`、不经过那次 POST。**

### 进入主界面之后：安装**全程离线**

```
MainActivity 首页按钮
  → b.smali:419-461  Y() → S()
  → S() 只需设备管理器已激活（e/b.smali:1588-1601 isAdminActive）
  → e/b.a()（e/b.smali:1023-1113）取包列表
      ← e/b.smali:141 → UpdateInstance.c → c.smali:1052-1128
      ← 来源是【assets/Xpp_Q.json】，不是网络
  → 逐个从 assets 解出 APK
      assets/com.google.android.gms_29.apk                  90,657,638 B
      assets/com.google.android.gsf_29.apk                   3,923,176 B
      assets/com.android.vending_29.apk                     21,168,579 B
      assets/com.google.android.syncadapters.contacts_29.apk 1,457,061 B
      assets/com.oversea.gmapjar_29.apk                        154,359 B
      （外加整套 _28，共 13 个）
  → e/b.smali:456  c/a.a(path, md5) 预检命中 ⇒ 【完全跳过下载】
  → 华为 DevicePackageManager.installPackage(cn, Uri)
```

**⇒ 原版 APK 持有 `MDM_INSTALL_SYS_APP`（实测 true）⇒ 静默安装可行，零联网。**

### 需要的三个前置条件（全是用户侧）

| 条件 | 说明 |
|---|---|
| **时钟在 CER 有效期内** | `META-INF/HUAWEI.CER`：**2019-10-14 → 2020-10-14**，PMS 在**安装时**检查 |
| **设备管理器已激活** | `dm/DeviceManageReceiver` |
| **Wi-Fi 开启** | 首页安装按钮有 `NetworkUtil.b()`（`getNetworkInfo(TYPE_WIFI).isConnected()`）检查；失败对话框有**继续**按钮（b.smali:338-381）可绕过 |

### 触发命令

```powershell
# 方式一：广播（已确认导出）
adb shell am broadcast -a com.x.plus.pro.UpdateNotifyClick `
  -n com.qiyecomm/com.x.plus.pro.update.UpdateNotificationReceiver

# 方式二：直接启动 Activity（shell UID 通常被豁免 exported 限制，未实测）
adb shell am start -n com.qiyecomm/com.x.plus.pro.MainActivity
```

**⚠️ 无用户可操作的路径**：`SplashActivity` 是唯一的 LAUNCHER Activity，
`MainActivity` / `UpdateDialogActivity` / `RegisterActivity` 都没有 intent-filter。
**⇒ 只能通过 adb 或另一个 App 触发。**

## 三、顺带确认的两件事

### ① 华为备份**确实无视** `allowBackup="false"`

**直接证据**：那份成功还原过的 lzplay 备份包

```
…/2019-12-07_02-08-38-841/
  ├── com.lzplay.helper.apk   3,070,790 B   ← 其清单里 allowBackup="false"
  ├── com.lzplay.helper.tar   1,264,128 B   ← 却含完整 data/data/com.lzplay.helper/ 树
  └── info.xml                3,745 B
```

tar 里有 **105 个条目**，含 `shared_prefs/com.lzplay.helper.xml`(5258 B)、
`databases/filedownloader.db`、`files/`、`cache/`。

而设备上还原后 `installerPackageName = com.huawei.localBackup`（第一阶段记录）。

**⇒ 投递机制是真实有效的**（只是对旅游助手没有可投递的有效载荷）。

**⚠️ 但伪造新备份包仍有未知**：`info.xml` 的 `BackupFileModuleInfo.checkMsgV3`
（`<64 hex>_<64 hex>` 格式）语义未明，`hwbackup_dec.cjs` 从不校验它，
**还原端是否校验未知** —— 这是投递路径唯一的悬念。

### ② 旅游助手**没有加固**

全树 grep `jiagu|StubApp|com.stub` = **0 命中**；Application 类是
`com.x.plus.pro.base.BaseApp`（不是 lzplay 那种 `com.stub.StubApp`）。

**⇒ 与 lzplay 那边的 `libjiagu.so` 无关，杀毒软件的影响不涉及这条线。**

## 六、诚实声明的不确定项

1. **`BackupFileModuleInfo.checkMsgV3` 是否被还原端校验** —— 决定能否伪造备份包
2. **华为备份 App 会不会备份 `allowBackup=false` 的应用** —— 只证明了**还原**无视该标志
3. **那份 lzplay 备份包是否由华为备份 App 生成**（vs 教程作者手工构造）—— 磁盘上无法证明
4. **`adb shell am start` 能否启动非导出 Activity** —— 源自 AOSP 的 shell UID 豁免，未实测
5. **§2 那条链从未端到端跑过** —— 每一步都从 smali 读出，但设备上只验证到「卡在 Splash」
6. **`e/c.a()` 里 `hwFlags & 0x2000000` 的含义** —— 行为上已知（当前返回 false，流程继续），语义不明
