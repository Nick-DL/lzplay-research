## 二、设备是否已信任 NDC 根证书？→ **目前看：没有**

用设备上的 `curl` 测两个端口：

```
port 18443 (NDC 签的)  : -k(忽略证书) = 200   |  严格校验 = 000
port 18444 (自签)      : -k(忽略证书) = 200   |  严格校验 = 000
```

**⇒ 两个严格校验都失败。**

**⚠️ 但这个结论对 App 不适用** —— `curl` 用**自己内置的 CA 包**，不用系统信任库。
而 App（`HttpsURLConnection`）用的是**系统信任库**，会认用户安装的 CA。

**⇒ 必须用 Java 探针才能得到对 App 有意义的答案。**

**当前状态**：`TlsProbe` 已写进 LZRevive 并构建，但**后台线程没跑完**
（报告里只有段头，结果文件没生成）。**原因待查。**

## 三、✅ 请你安装 CA 证书（一次性）

### 安装步骤（HarmonyOS 4.2）

```
① 设置
② 安全
③ 更多安全设置
④ 加密与凭据
⑤ 从存储设备安装   （或「安装证书」）

⑦ 会警告"您的数据将不再私密" → 点【仍然安装】
⑧ 文件管理器里找到 Download/ndc-ca.crt → 选中
```

**装完后核对**：
```
设置 → 安全 → 更多安全设置 → 加密与凭据 → 信任的凭据 → 【用户】页签

```

**⚠️ 如果你看到 `ND Certification` 已经在那里了** —— 那就说明它本来就装了，
`curl` 的失败只是因为它不用系统信任库，**不用再装**。

## 四、装好之后的下一步

```
① 扩展 ProxyVpnService：
     - DNS 层把 api.trip-happy.com 映射到 VPN_ADDR（已有基础设施）
     - 新增 443 端口处理
② 回环桥接 + TLS：
     new ServerSocket(0, 50, InetAddress.getLoopbackAddress())
     → 标准 SSLSocket 做握手（用 server.crt/server.key）
     → 读 HTTP 请求 → TripHappyResponder → 写回响应
③ 响应字节回灌到 VPN 的 TCP 栈
④ 端到端实测
```

**为什么用回环桥接**：这样能直接用**标准 `SSLSocket` API**，
不必手写 `SSLEngine` 的 record 层。工作量与风险都大幅下降。
