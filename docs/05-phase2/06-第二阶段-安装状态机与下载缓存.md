## 一、安装流程状态机（按顺序列出状态）

### 1.1 涉及的角色

| 类（smali 文件） | 原 Java 名 | 职责 |
|---|---|---|

| `com/x/plus/pro/e/c` | `InstallHelper.java` | 真正调用安装/卸载 API，广播回执，超时兜底 |

### 1.2 两个「状态」要分清

* **流程状态 `com/x/plus/pro/e/b;->f:I`**（`e/b.smali:43`）
  `0`=空闲/未开始，`1`=下载中，`2`=卸载中，`3`=安装中。
  由 `b()/c()/d()` 分别写入（`e/b.smali:1501`、`1532`、`1580`），
  `b.T()`（`b.smali:182-231`）用它做 `packed-switch` 来恢复/继续流程。
* **界面状态 `com/x/plus/pro/b;->ah:I`**（`b.smali:42`），取值 `0..6`，
  由 `c(int)`（`b.smali:499-967`）渲染，与 `e/b` 的消息号一一对应（见 1.4）。

`e/b` 内部还有三个并发队列与一个计数器：

* `m:Queue` 下载队列（`e/b.smali:53-61`）
* `o:Queue` 卸载队列（`e/b.smali:73-81`）
* `n:Queue` 安装队列（`e/b.smali:63-71`）
* `e:I` 当前序号/已失败次数（`e/b.smali:41`，`+=1` 见 `e/b.smali:369-373`、`1350-1354`）
* `p:J` 全部 APK 字节总数，**初值 -1**（`e/b.smali:110-113`，累加见 `e/b.smali:861-869`）

### 1.3 阶段 0：启动与准备

1. 界面 `b.S()`（`b.smali:107-152`）：隐藏按钮 → 若已是设备管理员
   （`e/b.e()` = `DevicePolicyManager.isAdminActive`，`e/b.smali:1588-1601`）
   → `c(2)`（界面状态 2）→ **`e/b.a()V`**；否则 `e/b.f()` 拉起
   `android.app.action.ADD_DEVICE_ADMIN` 授权（`e/b.smali:1603-1634`）。
2. `e/b.a()V`（`e/b.smali:1023-1113`）= 复位并装配：
   * `f=0`、`e=0`（`e/b.smali:1029-1032`）
   * `n()`（`e/b.smali:782-835`）：把 `pkgName → sign_256` 建成 `HashMap`，
     再塞一条 `com.x.idhelper → 6260FABB…`，调用
     `e/c.a(HashMap)` → `DevicePackageManager.setSysAppList(componentName, map, bundle)`
     （`e/c.smali:497-547`，`privPermission=true, undetachable=false, addItem=true`）
     —— 即「把这些包登记为系统应用」，失败被 `catch` 吞掉。
   * 遍历清单：`ApkInfo.j = a(ApkInfo)`（见 1.5 的状态判定），
     并计算下载目标路径 `ApkBaseInfo.f = 根目录 + "/" + pkgName + ".apk"`
     （`e/b.smali:1074-1101`）。
   * `o()`（`e/b.smali:837-931`）：累加 `p`，并为每条 APK 计算
     **进度权重 `ApkInfo.k = round(fileSize × 50 / p)`**（`e/b.smali:903-925`）。
   * 最后 `b()` —— 进入阶段 1。
3. `ApkInfo.j` 的取值语义（`e/b.a(ApkInfo)I`，`e/b.smali:935-1021`）：
   `0`=未安装；`1`=已安装且 versionCode≥清单 `verCode`、已装签名==`sign_1`、
   且是系统应用（`ApplicationInfo.flags & 1`）；`2`=其它（已装但需替换/非系统应用）。
   ⚠️ 但紧接着 `e/b.smali:1065-1070` 又做了归一化：
   ```smali
   if-eqz v2, :cond_0      # j == 0 → 保持 0
   const/4 v2, 0x2
   iput v2, v1, ...->j:I   # j != 0 → 一律写成 2
   ```
   所以**流程里 `j` 只可能是 0 或 2**，`h()` 里 `j==1` 的快捷分支实际不可达（见第七节）。

## 二、更新检查失败时的行为（明确回答：**走本地清单兜底，不 abort**）

### 2.1 更新检查是哪条链

```
SplashActivity → a/a (DeviceHelper) → a/b (DeviceManage) → 消息 200
   → a/a$2 (a/c 实现) → new a/a$a Handler → sendEmptyMessageDelayed(1, 1000)
   → a/a$a.handleMessage → update.e.a(ctx, a/a.d)          (a/a$a.smali:73-80)
   → update.c.a(Context, "https://api.trip-happy.com/index.php/upgrade/info/", update/b)  (update/e.smali:73-84)
   → HTTP POST (f/d$a POST, 超时 5000ms)                    (update/c.smali:1540-1604)
   → 回调 update/c$1
```

`update/c$1.a(d$e)`（**网络失败/异常回调**，`update/c$1.smali:43-64`）只做一件事：

```smali
iget-object v0, p0, ...->b:Lcom/x/plus/pro/update/b;     # onFailure 回调
if-eqz v0, :cond_0
  iget-object p1, p1, Lcom/x/plus/pro/f/d$e;->d:Ljava/lang/Throwable;
  invoke-virtual {p1}, Ljava/lang/Throwable;->getMessage()Ljava/lang/String;
  invoke-interface {p0}, Lcom/x/plus/pro/update/b;->a()V
:cond_0
return-void
```

即：**失败仅调用一次 onFailure，不写任何缓存、不影响任何后续流程**。
成功路径才会解析 `data.upgradeConf` + `data.upgradeConfSign`，用
`md5(base64(upgradeConf) + "abksfsijifefe")` 校验签名（`update/c$1.smali:113-159`），
通过后把 `upgradeConf` 写入 SharedPreferences `com.x.plus.pro.update.updateUpgrade`
（`update/c.smali:391-443`）。

### 2.2 失败后是否还能拿到 APK 清单：能

* 失败回调在 Splash 侧是 `a/a$1.a()V`（`a/a$1.smali:38-45`）：

  ```smali
  .method public final a()V
      invoke-virtual {p0}, Lcom/x/plus/pro/a/a$1;->b()V     # ← 与成功回调同一个 b()
  ```
  `b()`（`a/a$1.smali:47-91`）= `startActivity(new Intent(SplashActivity, MainActivity)); finish();`
  **成功与失败都会进 MainActivity**。
* APK 清单**完全本地**：`com/x/plus/pro/update/c.a(Landroid/content/Context;)Ljava/util/List;`
  （`update/c.smali:1052-1128`）：

  ```smali
  sget p0, Landroid/os/Build$VERSION;->SDK_INT:I
  const/16 v0, 0x1c
  if-ne p0, v0, :cond_0
  const-string p0, "Xpp_P.json"          # SDK == 28
  :cond_0
  const-string p0, "Xpp_Q.json"          # 其它情况
  sget-object v0, Lcom/x/plus/pro/update/c;->b:Ljava/lang/String;   # "abksfsijifefe"
  invoke-static {v0}, Lcom/x/plus/pro/b/b;->a(Ljava/lang/String;)Lcom/x/plus/pro/b/a;   # RC4
  invoke-static {p1, p0}, Lcom/x/plus/pro/f/c;->a(Landroid/content/Context;Ljava/lang/String;)Ljava/lang/String;  # 读 assets
  invoke-interface {v0, p0}, Lcom/x/plus/pro/b/a;->a(Ljava/lang/String;)Ljava/lang/String;   # 解密
  sget-object p1, Lcom/x/plus/pro/update/c;->d:Lcom/a/a/e;   # Gson
  ... → beans/config/a → .a:Ljava/util/List;
  ```
* 该方法的唯一消费者是 `update.e.c(ctx)`（`update/e.smali:172-215`），
  它把结果缓存到静态 `e.c` 并用 `e$a`（按 `ApkBaseInfo.i`/`number` 升序，
  `update/e$a.smali:32-53`）排序后返回。
* **清单在安装管理器构造时就同步读进来了**：

  ```smali
  # com/x/plus/pro/e/b;-><init>(Landroid/content/Context;Landroid/os/Handler;)V  (e/b.smali:104-207)
  .line 90
  invoke-static {p1}, Lcom/x/plus/pro/update/e;->c(Landroid/content/Context;)Ljava/util/List;
  move-result-object p2
  iput-object p2, p0, Lcom/x/plus/pro/e/b;->b:Ljava/util/List;      # 字段 b = APK 清单
  ```
  构造点是 `b.a(LayoutInflater,ViewGroup)`（`b.smali:1422-1432`），即 Fragment 创建视图时。

**结论**：`UpdateInstance.a / c.a(ctx,url,callback)` 与 GMS 安装流程**没有任何依赖关系**。
更新检查只服务于「旅游必备自身升级」（下载到 `根目录/updatefile.apk`，

## 五、能否预置 APK 绕过下载（结论 + 做法）

### 5.1 结论：**能，而且有三重保险；本 app 甚至自带离线 APK**

1. **App 自己的「文件已就绪」预检**——`com/x/plus/pro/c/a.a(path, md5)`
   （`c/a.smali:36-93`）：

   ```smali
   new-instance v0, Ljava/io/File; <init>(p0)
   invoke-virtual {v0}, Ljava/io/File;->exists()Z
   invoke-virtual {v0}, Ljava/io/File;->isFile()Z
   invoke-static {p0}, Lcom/x/plus/pro/f/c;->b(Ljava/lang/String;)Ljava/lang/String;   # 文件 MD5
   invoke-virtual {p0, p1}, Ljava/lang/String;->equals(Ljava/lang/Object;)Z            # == 清单 fileMd5
   ```
   命中 ⇒ `e/b.h()` 直接 `k()`，**根本不创建 FileDownloader 任务**。
   它检查的路径是 `ApkBaseInfo.f`，即 `根目录/<pkgName>.apk`。
2. **assets 自带 APK 解包**——`ApkInfo.a(Context)`（`ApkInfo.smali:83-206`）
   把 `assets/<pkgName>_29.apk` 复制到 `根目录/<pkgName>_29.apk`，
   校验 MD5 后把 `ApkBaseInfo.f` 指向它并回调 `true` → 同样不下载。
   已有文件（长度>0）会被 `FileUtil.a(ctx,asset,dest)` 直接复用、不重复复制
   （`f/c.smali:296-323`）。
3. **FileDownloader 的 reuse 分支**（4.4 节）：即使前两步都没命中，
   只要目标路径已有文件且 `forceReDownload=false`，库会立刻投递 `completed`，
   不联网。随后 `e/b$4.a(task)` 做 MD5 校验（第六节）。

### 5.2 三种可用做法（按推荐顺序）

**做法 A（零操作）**：什么都不做。assets 里已有的 APK 与清单 MD5 **完全一致**，
`ApkInfo.a()` 的离线解包路径本身就能走通。实测（本仓库）：

| 清单条目（Xpp_Q.json） | 期望 fileMd5 | `work/travel_decoded/assets/*_29.apk` 实测 MD5 | 一致 |
|---|---|---|---|
| com.google.android.gms | `29c0b6feb1ad1b514687b8b733644f55` | `29c0b6feb1ad1b514687b8b733644f55` (90 657 638 B) | ✅ |
| com.google.android.gsf | `95a3c04f3fa1bef6ed41d749ab507966` | `95a3c04f3fa1bef6ed41d749ab507966` (3 923 176 B) | ✅ |
| com.google.android.syncadapters.contacts | `8f3de57a7040586b0e72a63e5a7edfb8` | `8f3de57a7040586b0e72a63e5a7edfb8` | ✅ |
| com.oversea.gmapjar | `3dd591e51f95faed12950f5df5152996` | `3dd591e51f95faed12950f5df5152996` | ✅ |
| com.android.vending | `9ed188488b8c6745f892fdb931419ee6` | `9ed188488b8c6745f892fdb931419ee6` | ✅ |

（`Xpp_P.json` 与 `*_28.apk` 同样 100% 一致，含 `policy_sidecar_aps_28`、
`backuptransport_28`。）

  ⚠️ 对应关系必须成对：设备 `SDK_INT == 28` 时读的是 `Xpp_P.json`，
  该清单的 gsf/contacts/gmapjar/vending 四条 MD5 只与 `*_28.apk` 匹配；
  而本仓库的补丁已把 `ApkInfo` 的 asset 名写死成 `_29.apk`
  （`ApkInfo.smali:104-106`），因此在 Android 9（SDK 28）设备上
  做法 A 会 MD5 不匹配 → 删文件 → 回落下载。
  本项目目标机型（Android 10+，`SDK_INT != 28`）读 `Xpp_Q.json`，
  与 `_29.apk` 完全配对，做法 A 成立。

**做法 B（预置到 `根目录/<pkgName>.apk`，最稳）**：
在 app 启动流程之前把清单里的 APK 放到 app 的外部缓存目录：

```
/storage/emulated/0/Android/data/com.qiyecomm/cache/com.google.android.gms.apk
/storage/emulated/0/Android/data/com.qiyecomm/cache/com.google.android.gsf.apk
/storage/emulated/0/Android/data/com.qiyecomm/cache/com.google.android.syncadapters.contacts.apk
/storage/emulated/0/Android/data/com.qiyecomm/cache/com.oversea.gmapjar.apk
/storage/emulated/0/Android/data/com.qiyecomm/cache/com.android.vending.apk
```

文件内容必须与清单 `fileMd5` **逐字节一致**（可直接用 `assets/<pkg>_29.apk`）。
这样 `e/b.h()` 的 `c/a.a(path,md5)` 命中 → `k()`，连 assets 解包和
FileDownloader 都不会走。不需要 `.temp`、不需要 `filedownloader.db` 记录、
不需要伪造任何元数据。（若同时想绕过做法 A 的 assets 解包，可把同样的文件
再放一份到 `根目录/<pkgName>_29.apk`，`FileUtil.a()` 见到非空文件会直接复用。）

**做法 C（只依赖库的 reuse）**：同做法 B，但即使 MD5 对不上也会被库当成
「已完成」（因为长度不校验），**不过**随后 app 自己的 MD5 校验会失败并删文件
（见第六节），因此**实质要求与做法 B 相同**。

### 5.3 阻碍与注意事项

* **MD5 必须匹配**：不匹配时 `e/b$4.a(task)` 会 `f/c.a(path)`（删除文件）
  并当作下载失败（`what=2` → 界面状态 3，失败 3 次进状态 4）。放错文件比不放更糟。
* **安装阶段结束后会清理**：`j()` 队列空时会遍历清单删除所有
  `ApkBaseInfo.f` 指向的文件（`e/b.smali:598-606`）。所以预置要在流程开始前做完；
  跑完一轮后需要重新放。
* **设备管理员/系统应用登记**：`n()` 会调用 `DevicePackageManager.setSysAppList(...)`，
  失败被吞掉，不影响流程；但安装本身在原始代码里走
  `DevicePackageManager.installPackage`（需要设备管理员 + 华为特权接口），
  本仓库已把该分支补丁成普通 `ACTION_VIEW` 安装。
* **路径可写性**：`getExternalCacheDir()` 在 Android 10/11 上只能用 adb/root 或
  同 uid 进程写入；不能靠 `run-as`（非 debuggable）。也可让代理进程以
  app uid 运行来写。
* **`fileSize` 不参与校验**：reuse 分支用真实文件长度当 `total`，
  app 侧只看 MD5，所以文件大小只需与真实 APK 一致（由 MD5 保证）。
* 由于 5.2 的做法 A 已成立，**严格来说「本地代理下载」并非必需**：
  只有当日志证明 assets 解包失败（例如目标路径不可写、MD5 不符）时，
  才需要代理接管 `http://cdn-trip-happy.sg.ufileos.com/...` 与
  `http://cdn.trip-happy.com/...` 这两个下载域名。

**一句话**：下载/解包**之后、安装之前**确实有 MD5 校验（#3、#2），
不通过就删文件并把该 APK 记为失败；安装**之后**不再校验文件 MD5，
而是靠系统的 `PACKAGE_ADDED` 广播 + `versionCode/签名` 前置判断。
