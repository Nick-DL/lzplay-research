# 第二阶段：代理方案最终结论（实测裁定）

> **结论：在「不改包 + 无 root」的前提下，伪造 `api.trip-happy.com` 的响应不可行。**
>
> 这不是推测 —— 是四项受控实验 + 一份全量代码审计的结果。

---

|---|---|---|
| 原版是否必须改包 | ❌ "原版必然崩溃" | ✅ **不需要改包**（GMS 未装时不 OOM） |

**原版在全新安装环境下实测**：

## 二、四项受控实验（基线全部有效）

设备：Mate50 `DCO-AL00` / HarmonyOS 4.2 / **未 root**。
PC：`192.168.3.37`。所有服务端证书 SAN 同时含 `DNS:api.trip-happy.com` 和 `IP:192.168.3.37`，
**排除主机名不匹配这个干扰项**。

| # | 用例 | 结果 | 判定 |
|---|---|---|---|
| **A** | `https://www.google.com/generate_204`（真 CA） | **HTTP 204 in 229 ms** | ✅ **基线有效** |
| **B** | NDC 用户 CA 签发 | `CertPathValidatorException: Trust anchor for certification path not found` (91 ms) | ❌ |
| **C** | 自签证书 | 同上 (29 ms) | ❌ |
| **D** | **明文 HTTP 发到 TLS 端口** | `javax.net.ssl.SSLException: Unable to parse TLS packet header` (13 ms) | ❌ |

**D 是最关键的一项**：13 毫秒就返回 SSL 协议错误，**不是超时** ⇒
**我们代理的字节确实到达了 App，是 TLS 协议层拒绝了它。**

⇒ 你提出的两个方向（**直接 HTTP 回复**、**用不可信证书回复**）**都实测被拒**。

## 四、代码审计结论（全量，1634 个 smali）

| 问题 | 结论 |
|---|---|
| 非 TLS / HTTP 回退路径 | **没有**。URL 是硬编码 `https://` 字面量（`update/e.smali:64`、`:79`），无分支无回退 |
| TLS 配置 | **平台默认**。全 APK grep `SSLSocketFactory`/`HostnameVerifier`/`TrustManager`/`SSLContext`/`checkServerTrusted` = **0 命中**；无 pinning；无 `networkSecurityConfig` |
| 明文响应时走哪个回调 | `d$f.smali` 所有 catch 都是 `Throwable` → `d$e->d` → `d$b->a(d$e)`（失败回调）→ `update/c$1.a()` → **弹窗**。异常类为 `SSLHandshakeException`/`SSLException` |
| 可控制的请求头 | **没有**。只有硬编码的 `Connection: Keep-Alive` + `Content-Type: application/json` |
| 响应头影响行为 | **没有**。`d$e->c`（响应头）只有写入点，**无读取点** ⇒ 连 `Location` 都不影响 |
| 系统属性 / 环境变量 / 文件 / SharedPreferences 注入 | **没有**。`System.getProperty` 全 APK 仅 1 处（`java.version`，Gson）；`Settings` 读取仅 1 处（`android_id`，只作请求 uuid）；配置只从 **assets** 读 |

### 全部候选注入点

| 向量 | 可行性 |
|---|---|
| 导出广播 `UpdateBroadcast` / `UpdateNotifyClick` | **能触发不能注入**（忽略 extras）—— 可用来按需制造请求时间窗 |
| `settings put global http_proxy`（adb 可写，无需 root） | https 只有 CONNECT 隧道，**不能解密** |
| DNS/hosts/路由器/ARP 重定向 | **仅 DoS**（无受信证书） |
| 用户级 CA 中间人 | ❌ **实测排除** |
| 系统级 CA（改 `/system/etc/security/cacerts`） | 有效，**需 root** |
| Frida/Xposed hook 平台 SSL 层 | 有效，**需 root**（App 非 debuggable，不能注入 gadget） |
| 写 SharedPreferences 缓存响应 | `allowBackup=false` + 无 `debuggable` ⇒ `adb backup`/`run-as` 都不可用 ⇒ **需 root** |
| 预放 `updatefile.apk` | 下载目录是**内部** cache（SDK>28）；且安装前校验 md5/包签名，两者都取自响应 ⇒ **不可伪造** |
| 控制 `api.trip-happy.com` 域名本身 | **域名未释放**（解析到 Cloudflare，WHOIS 显示 TripHappy 仍活跃）⇒ **不可行** |
| 改包 | 被"不改包"前提排除（且会毁 CER） |

**⇒ 不改包、无 root 时，不存在能让 App 接受伪造响应的注入点。**

## 五、一个有价值的技术发现

**响应的"签名"是 MD5 校验和，不是 HMAC —— 没有服务器密钥。**

```
upgradeConfSign = MD5hex( Base64_NO_WRAP( UTF8(upgradeConf) ) + sign )
sign            = MD5hex( "brand=..model=..product=Triptime=..uuid=.." + "XPP" )
```

依据：`update/c$1.smali:86-159`、`f/k.smali:30`（"MD5"）、`f/k$2.smali:46-54`（`getBytes("utf-8")`）、
`f/a.smali`（Base64Util，`encodeToString([BI)` flags=0xa）。

**⇒ 任何能读到请求的人（终止 TLS / 控制服务器）都能为任意 `upgradeConf` 算出合法签名。**
**⇒ 一旦解决 TLS，协议侧没有任何障碍。**（我们的响应器已实测通过 App 的校验逻辑。）

## 七、可行的前进方向

| 方向 | 需要 | 说明 |
|---|---|---|
| **① 拿到 root** | 解锁 bootloader / 工程机 | 最直接。有了 root 可装系统 CA，**原版完全不用改**，整条链立刻打通 |
| **② 换一台可 root 的设备** | 任意 Android 9+ 且能 root 的华为机 | 同样有效（需 HarmonyOS 提供 `DevicePackageManager`） |
| **③ 利用厂商测试入口** | 华为工程模式 / `adb root`（零售机不给） | 值得一试 |
| **④ 回到改包路线** | 接受丢 MDM 特权 | 那就要同时解决 `REQUEST_INSTALL_PACKAGES`（二进制清单补丁）|
| **⑤ 接受现状** | — | 第一阶段目标已达成；用改包版 + 手工 adb 装 GMS |

**推荐顺序：① → ② → ③ → ④ → ⑤**

**如果这台 Mate50 不是你的主力机，① 是最优解** —— 它让「不改包 + 静默安装 + 无需用户操作」
三个目标同时成立，正是你最初想要的效果。

## 八、诚实声明的不确定项

1. 明文响应时 Conscrypt 的**确切异常文案**随版本变化（我们实测到 `Unable to parse TLS packet header`），异常**类别**确定
2. 运行时是否拒绝 https→http 降级重定向 —— 框架行为，APK 内不可判定（**但不影响上述结论**，因为 `Location` 只能来自终结 TLS 的一方）
3. 未实测「root 后装系统 CA」这条路的端到端效果（设备未 root，无法验证）
