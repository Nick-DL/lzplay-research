# 三台华为设备对照 —— "机型白名单"之谜的答案

> 用同一个探针（`LZGateProbe`）在三台设备上调用 lzplay 依赖的那个华为 API，
> 直接测出 lzplay 的门禁到底在判什么。
> **结论：不存在"机型白名单"。门禁只是一个反射调用，唯一拒绝的情况是「华为 API 不存在」。**

---

## 一、三台设备

| | Mate50 Pro | Nova7 | MatePad Pro 2022 |
|---|---|---|---|
| 型号 | DCO-AL00 | JEF-AN00 | GOT-W09 |
| 系统 | HarmonyOS 4.2.0 | HarmonyOS 4.2.0 | HarmonyOS 4.2.0 |
| 内部版本 | — | `4.2.0.121(C00E121R5P5)` | `4.2.0.237(C00E100R9P7)` |
| Android / SDK | 12 / 31 | 12 / 31 | 12 / 31 |
| EMUI | EmotionUI_14.2.0 | EmotionUI_14.2.0 | EmotionUI_14.2.0 |
| 安全补丁 | 2022-08-01 | 2021-10-05 | 2022-08-01 |
| lzplay 表现 | **卡在启动页** | （几年前成功过） | **弹"暂不支持该设备"** |

**三台系统版本完全一致。** 所以"版本白名单"在版本层面无从谈起。

---

## 二、探测结果

探针调用的是 lzplay 门禁那一行（`DeviceManage.java:92`）：

```java
new com.huawei.android.app.admin.DevicePackageManager()
    .getSysAppList(new ComponentName(this, DeviceManageBC.class), [getPackageName()])
```

| 设备 | `DevicePackageManager` 方法数 | `getSysAppList` | 实际调用结果 | **lzplay 的判定** |
|---|---|---|---|---|
| **Mate50 Pro** | **35** | ✅ 存在 | 抛 `android.os.RemoteException` | **SUPPORTED** |
| **Nova7** | **35** | ✅ 存在 | 抛 `android.os.RemoteException` | **SUPPORTED** |
| **MatePad 2022** | **33** | ❌ **不存在** | `NoSuchMethodException` | **UNSUPPORTED** |

类都从 `java.lang.BootClassLoader` 加载（即 framework 提供，非 APK 内嵌桩）。

---

## 三、lzplay 门禁的真实逻辑

`com.lzplay.helper` 内层 `DeviceManage.java:92` 反编译：

```java
if (Build.VERSION.SDK_INT < 28) return false;

try {
    new com.huawei.android.app.admin.DevicePackageManager()
        .getSysAppList(ComponentName(this, DeviceManageBC.class),
                       new ArrayList() {{ add(getPackageName()); }});
    return true;                                    // 调用成功 → 支持
} catch (Throwable t) {
    if (t instanceof NoSuchMethodError
        || t.getClass().getName().equals("com.huawei.android.util.NoExtAPIException"))
        return false;                               // ← 只有这两种算"不支持"
    return true;                                    // ★ 其它一切异常都算"支持"
}
```

**唯一被拒绝的情况：华为的类或方法不存在。**
权限不足（`SecurityException`）、远程失败（`RemoteException`）—— **全部放行**。

**所以：**
- 没有设备名单文件
- 没有服务器查询
- 没有机型/版本比较
- 只有一个**本地 API 存在性检查**

## 四、逐台解释

### MatePad 2022（GOT-W09）—— 弹"不支持"

**华为真的没实现那个方法。**

```
method count: 33              ← 比另两台少 2 个
getSysAppList present: false
getMethod(getSysAppList, ComponentName, List) -> NoSuchMethodException
```

它的 `DevicePackageManager` 只有 33 个方法，缺的正是 `getSysAppList` / `setSysAppList`
（"查询/设置系统应用白名单"能力模块被砍掉了）。

⇒ **不是 lzplay 限制太严，是这台平板的华为框架确实缺了它依赖的 API。**
⇒ lzplay 无法"放宽"来支持 —— 没有那个接口它做不了核心功能。
⇒ **lzplay 的判断是技术性正确的。**

### Mate50 Pro（DCO-AL00）—— 卡在启动页

```
method count: 35
getSysAppList present: true
THREW: android.os.RemoteException
---- lzplay 的判定 ----
   SUPPORTED
```

**门禁说"支持"。** 所以卡启动页**与门禁无关** —— 这也解释了为什么没弹"不支持"对话框。

（`RemoteException` 是因为探针把 `ComponentName` 指向了未注册为设备管理员的组件；
换 lzplay 自己的 `DeviceManageBC` 就不会。但**这不影响结论** —— 无论抛什么，
只要不是 `NoSuchMethodError`/`NoExtAPIException`，lzplay 一律判"支持"。）

### Nova7（JEF-AN00）—— 成功过

与 Mate50 **完全相同的 API 面貌**（35 个方法、`getSysAppList` 存在、判定 SUPPORTED）。

⇒ 它的成功与 Mate50 的门禁结果**没有区别**，差别在别处（当年服务器还活着）。

## 五、Mate50 卡启动页的可能原因（待验证）

按可能性排序：

1. **卡在服务器请求** —— lzplay 2019 年的 API 早已下线，请求超时挂住。
   （Nova7 当年成功时服务器还在。）
2. **360 加固外壳初始化失败** —— 脱壳分析中已发现它的 VM 解码器逻辑复杂。
3. **时区/时钟相关的证书链等待** —— 但门禁本身已放行，排除门禁。

**建议的验证方法**：抓 lzplay 卡住时的完整 logcat 与网络请求（`netstat`/`tcpdump`），
看它停在哪个 socket 或哪个加固 VM 阶段。

## 六、副产品：MatePad 上有华为自己的 GMS 桩包

```
com.google.android.gsf    v0.1.0
com.google.android.gms    0.3.2.240913-hw      ← "-hw" 后缀 = 华为定制
```

这是华为的 GMS 兼容层（用于出海应用/HMS 桥接），**与 Google 正品不是一回事**，
签名也不同（华为签的）。Nova7 和 Mate50 上没有这两个包。

值得注意：**如果华为自己实现了 `com.google.android.gsf` 这个包名，
那它就占用了 microG `GsfProxy`（包名同为 `com.google.android.gsf`）想要的位置。**
在 MatePad 上换用 microG 路线前必须先处理这个桩包。

## 七、对项目结论的影响

| 之前的说法 | 更正后 |
|---|---|
| "lzplay 内置白名单，弹'不支持'就说明机型不在名单里" | ❌ **没有白名单。** 只有 API 存在性检查 |
| "设备门禁是离线的" | ✅ 对，但它是**反射检查**，不是名单比对 |
| "改包可以解除白名单限制" | ❌ 无从下手 —— 没有可解除的名单 |
| "平板不能用 lzplay" | ✅ 对，因为华为砍了 `getSysAppList` |

**这一并解释了为什么三台设备中只有平板被拒** —— 只有它缺那个方法。
